# QA BUG 單 - 待修問題清單

## 強制規則

1. **只能用真實 GUI 驗收。** QA 必須使用已開啟且可見的微信開發者工具右側模擬器畫面操作；不得用 CLI、腳本、API、automation launch、直接改頁面狀態或路由跳轉取代真人點擊、輸入、返回、切頁與畫面觀察。除非使用者明示，不得新開、重啟或切換到新的微信開發者工具視窗。

2. **BUG 單只存目前未通過的修正問題。** 本文件不得存開發需求、MVP gate、產品完成度、backlog、Priority、下一步、摘要、歷史清單或第二張表；這些內容應移到對應文件。Status 只能是 `不通過`，通過項目必須從本清單移除，不得保留 `通過` 狀態列。

3. **每個 BUG 必須小到能單獨修、單獨測、單獨關閉。** 不得保留籠統 BUG；若一列包含多頁、多角色、多流程、多個驗收點，或讓開發者看不出要修哪個具體行為，QA 必須立刻拆成可單元測試的小 BUG，移除或改寫原籠統列，並補上具體畫面、操作、預期結果與可能位置。若其實是開發需求，必須移到 `MVP_COMPLETION_CHECKLIST.md`。

4. **每次都要重新實測並即時更新文件。** 本文件不是歷史紀錄；不得因舊文字、舊通過紀錄或 agent 過去自稱測過就關閉項目。驗收時每完成一列，就必須立刻回到本文件更新該列結果與證據，再繼續下一列；不得等全部測完才一次更新。

5. **回報必須可核對，不得含糊。** 每次回報必須先給簡短結論，再給統計數量：本次範圍總數、已測數、通過數、不通過數、未完成或需介入數。每個 `不通過` 都要附一行簡短原因；任何需要使用者介入的項目必須單獨列出並說明要使用者授權或決定什麼。只要仍有未完成、未驗證或需使用者介入項目，就不得回報「全部完成」「全部修好」或等同結論。
