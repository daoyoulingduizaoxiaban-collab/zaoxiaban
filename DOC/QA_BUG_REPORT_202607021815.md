# QA BUG 單 - 待修問題清單

## 強制規則

### QA 人工驗收硬規格

1. QA 必須使用你已開啟且可見的微信開發者工具右側模擬器畫面進行驗證；不再開啟新視窗、不重啟、不中斷現有 session（除非你書面要求）。
2. 禁止使用 `cli open / auto / preview / start / restart / refocus`，不得用 `automator.launch(...)`；不得使用 CLI 指令替代真人點擊路徑。
3. 除非你明示，單次 QA 不得自行啟動新的微信開發者工具視窗。
4. 禁止透過腳本、API 或非 UI 操作方式直接導向流程；所有主流程必須用可見 UI 的點擊、輸入、返回、切頁完成，並觀察畫面與路由一致性。
5. 回歸採「真人操作」方式執行，不得以程式輸入指令直接改變頁面狀態作為合格證據。

6. 本文件只保留 `修正問題`。開發需求、MVP gate、產品完成度與 backlog 必須寫在 `MVP_COMPLETION_CHECKLIST.md`，不得混在本 BUG 單。
7. 本文件不是歷史紀錄本。項目不能因為舊文字、舊通過紀錄或代理過去自稱測過就關閉；每次驗收都必須重新從目前版本完整操作一次。
8. 每一列都必須能被單獨修正、單獨驗收、單獨關閉。不能把多頁、多角色、多流程或多個驗收點塞在同一列。
9. 不得保留 `通過` 項目。修好並驗收通過後，從本清單移除；若仍有衍生問題，另開一列具體問題。
10. 不得新增 Priority / 優先級、下一步、摘要、補充清單、歷史清單或第二張表。
11. 不得保留籠統項目。若一列無法說清楚要修正哪個問題，必須拆小、改寫或移除；若它其實是開發需求，必須移到 `MVP_COMPLETION_CHECKLIST.md`。
12. Status 只能寫 `不通過`。本清單不存放已通過項目。
