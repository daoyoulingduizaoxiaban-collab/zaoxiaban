## 二、全功能检视（现在的主线：逐页面详查）

**目标**：让人能「正常且正确」地用每个功能。

**每行 = 一个页面 = 一个可独立完成的检视单元**：读该页代码 + 对照它的业务章节 + **分角色**（客户 / 团主 / owner / admin）走查下面 5 件事，一趟做完、不压缩上下文；做完更新该行「状态」，把要用户亲手测的写进「🔎 要你手动测」列，其余技术细节写进「主要发现」列。

**每页要查的 5 件事（镜头）**：
1. **入口**：进得来吗？位置合理/固定/不重复？每个角色该看到的看到、不该看到的别漏出？（对照 **B1**、**A4**、**B5**）
2. **操作 / 跳转 / 三态**：点下去顺吗？跳转对、回得来吗？加载中／失败／空 三态对吗？（**A11**、**A12**）
3. **字段**：每个栏位有用吗？有没有多余、该有却缺、填了没意义的？（对照该页资料模型与业务章节）
4. **角色**：这页对各角色的可见性/字段/操作，跟 **B1 矩阵** 一致吗？
5. **模组连动**：这页改的数据会牵动别的模组吗？反过来呢？（团单↔客户订单↔商品库↔数据中心；**A5**、**A6**）

> **【检视中发现「业务文件没规定」的逻辑，怎么处理】（规则，下一个 Claude 也照办）**
> - **明显该有、无争议**的逻辑（例：某状态显然该拦、某字段显然该带）→ **直接补进业务文件对应 Part**，让系统更完整，并在「主要发现」注明「已补 §x」。
> - **要不要做 / 怎么做需要用户拍板**的（涉及产品取舍、影响范围大、有多种合理做法、动到隐私/角色可见性策略）→ **不可擅自决定**，标「⚠️待你拍板」并**主动提出跟用户讨论**，谈定再补文件/改码。
> - **明显的一致性清理**（去重复入口、删冗余控件、两个重复留哪个、命名/布局对齐）→ **自己决定并落地，别问用户**，只需保持整体系统风格一致（用户 2026-07-22 指示）。
