### UI 写流程测试要点（登录优先·必读，`flow-grouporder.js` 已踩通）
1. **必须先首次登录**：`refreshSession` 只刷新已有会话、**不建首次登录**。要先 `reLaunch('/pages/login/login')` → `callMethod('login')`（本地模式 `AuthService.login` 只用 `wx.login`+owner openId，**无需 getUserProfile 手势**），会话建成后持久化在 storage，后续页 refreshSession 才有得刷。登录页在分包、reLaunch 偶发超时 → 做 **best-effort（try/catch）**，会话建一次即可。
2. **分包页 reLaunch 后用 `mp.currentPage()` 重取页面**：直接用 reLaunch 返回的句柄可能是过期页（data 全 undefined、方法不存在）。
3. **填表走 `page.setData({formData, selectedGoods})` + `callMethod('onSave')`**：绕开 t-button 选择器和跨页 picker，专注证明写流程。
4. **避开内部文案正则**：商品字段禁词 `QA|mock|test|local|测试|本地|自动化…`（`lib/core.js` `INTERNAL_PRODUCT_COPY_RE`）；团单存商品快照、不校验，用捏造 goods 即可。
5. **首个 automator 调用偶发超时/`getCurrentPagesByDomain`/`page destroyed`**：IDE 预热/重编抖动，**重跑即可**（`flow-review.js` 常需跑第 2 次）。
6. **reLaunch 后必须轮询等页面就绪**（`flow-review.js` 已用）：`currentPage()` 偶发拿到未就绪/过期页 → data 全 undefined。循环 `currentPage()`+`data()` 直到目标字段（如 `pageState`）非 undefined/非 loading，最多 ~8 次、每次 800ms。**这条解决了反复的「wrong page / undefined data」抖动，下条流照抄。**
7. **回查断言别靠"是否在 pending 列表"**：`users.listPending` 会把刚审过的也带回来 → 改读该用户当前 `reviewStatus`（approved/pending_review）判定。
8. **reLaunch 后必须校验真的落对页、不中就重试**（`flow-order.js` 的 `gotoPage`）：任何被 devtools 监视的**源码改动（如刚切 `config.js`）触发热重载**，会把模拟器导航**重置到编译起始页**并悄悄覆盖你的 reLaunch → 你以为进了目标页、其实停在 my/index（`page.data()` 字段全 undefined 即此症）。对策：reLaunch 后查 `currentPage().path` 命中目标子串，不中重试最多 5 次。**下条流照抄。**

- 自动化只证明**本地后端**这条路通。**云端**靠「地端云端双通」铁律的镜像代码保证——本地绿是强信号，不等于云端逐字相同。改数据层的云端动作必须同步改 `cloudfunctions/businessData`（否则正式环境报「资料操作不存在」）。
