## 二、自动化自测（2026-07-28 起）

**目的**：不靠人点，脚本驱动开发者工具跑真实操作，红了就地修，让功能可回归验证。

### 现有测试
| 脚本 | 测什么 | 怎么判定 |
| --- | --- | --- |
| `local-server/flow-test.js` | 报Bug 提交全流程（进页→填→提交） | 用唯一标记回查本地库，确认 UI 提交**真落库** |
| `local-server/automator-smoke.js` | 5 个核心页加载三态 | 停留后 `pageState` 非 loading/error 即 PASS |

### 怎么跑（连**已开**的开发者工具，勿重启）
1. 起本地后端：`node local-server/server.js`（改了云函数代码要**重启**它，它启动时才 require 一次）。
2. 临时切本地后端：`config.js` 的 `DATA_BACKEND` 改 `isProd ? 'cloud' : 'local'`（**测完 `git checkout -- config.js` 还原成 `'cloud'`**）。
3. 挂自动化端口到运行中的 IDE（不重启）：`"$CLI" auto --project "$(pwd)" --auto-port 9420`（CLI＝`/Applications/wechatwebdevtools.app/Contents/MacOS/cli`）。
4. 跑：`node local-server/flow-test.js`；`WS_ENDPOINT=ws://127.0.0.1:9420 node local-server/automator-smoke.js`。

### 本次跑出的结果
- ✅ 报Bug UI 提交 → 落库（marker 回查命中）。
- ✅ 团单 / 客户订单 / 商品库 三页加载 PASS（empty 态，无报错）；my / search 两页 SKIP（未接三态字段，非故障）。
- 🔧 **自测顺手修好 3 个真问题**：① local-server 是旧进程（不含 `feedbacks` 资源）→ 重启；② smoke 脚本 `msg.type()` 当函数调致崩溃 → 兼容属性/函数并包 try/catch；③ smoke `mp.waitFor` 应为 `page.waitFor`（automator 版本漂移）。

### ⚠️ 边界（务必认清）
- 自动化只证明**本地后端**这条路通。**云端**靠「地端云端双通」铁律的镜像代码保证——本地绿是强信号，不等于云端逐字相同。改数据层的云端动作必须同步改 `cloudfunctions/businessData`（否则正式环境报「资料操作不存在」）。
- 云函数**部署（上传并部署）是开发者工具 GUI 动作，CLI 做不到**——所以云端 FUNC 无法做「改→测→再改」的自修闭环，只能本地闭环 + 云端镜像。
