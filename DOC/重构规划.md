# 重构规划（可维护性）

针对「改一处要改多处」「胖页」「.js/.ts 混用」等增加修改难度的结构问题。
每项：**目标 / 范围 / 风险 / 完成判定 / 状态**。风险高的项必须**逐页在微信开发者工具实测**后才算完成（本项目无法 headless 编译）。

> 排序原则：先做安全、行为不变的机械清理（低风险立即做）；再做高价值但触及关键页的抽象（需逐页实测，谨慎推进）。

## R1. 抽共享「鉴权 + 三态」Behavior（最高价值，高风险，需逐页实测）
- **目标**：消灭 `customerOrders / groupOrder.ts / productManagement.ts` 三个 tab 页几乎 copy 的
  `onShow→refreshSession→权限判断→setData(isLoading/authReady/canUseBusiness/accessStateText/isLoggedIn/loadErrorText/pageState…)` 样板。
  改一次鉴权/加载逻辑只改 behavior 一处。
- **范围**：新增 `behaviors/useAccessPage.js`，封装：
  - onLoad/onShow 的 `refreshSession` 去重（含 `_skipNextShowRefresh`、in-flight 锁）。
  - access-state 计算（authReady/canUseBusiness/accessStateText/isLoggedIn/roleScopeText）。
  - 统一 `pageState` 三态脚手架 + 一个 `loadData()` 钩子由页面实现「我取什么数」。
  - 页面差异用配置/覆写留口：productManagement 的**公开目录**（非业务也有列表）、groupOrder 的 `isNavigatingCreate`、customerOrders 的操作面板。
- **风险**：Behavior 会合并进 Page 生命周期，顺序/`this` 细节出错难排查，且这三页是业务关键（订单/团单/商品）。**必须一页一迁移、每页单独 commit、用户逐页实测通过再迁下一页。**
- **完成判定**：三页行为与迁移前一致（四态、权限分支、筛选、FAB、公开目录），代码去掉重复样板；改动 behavior 一处即三页同时生效。
- **实现**：`behaviors/useAccessPage.js`（纯 helper：`buildAccessState(featureKey)`/`loadingState()`/`threeState(state,{errorText,emptyText,emptyCta})`/`hasFeature`；不劫持生命周期）。
- **状态**：
  - [x] behavior 建好；[x] **groupOrder 已迁试点**（成功/失败/筛选走 helper；权限拒绝分支保留显式取值；success/error 显式 `canUseBusiness:true` 保持原逻辑；.ts 用 `(this as any)` 兜 behavior 方法/data 类型）。**待用户在开发者工具实测这一页四态/权限/筛选/FAB**。
  - [ ] productManagement 迁移（注意公开目录：非业务也 loadPublic）；[ ] customerOrders 迁移（注意操作面板/详情弹窗）。
- **迁移准则（每页都遵守）**：一页一 commit、行为逐字段对齐（差异分支保留显式）、用户实测通过再迁下一页。
