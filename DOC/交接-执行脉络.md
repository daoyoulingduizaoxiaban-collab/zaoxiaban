## 2. ⚠️ 三件最容易搞錯的事

### 2.1 「本地後端」與「小程序內的假資料」是兩件事

使用者**只有微信雲開發免費版**，所以「能連本地資料庫測試」是硬需求。他已經為此糾正過三次，不要再問。

- ✅ **本地後端（保留）**：`local-server/` 直接跑同一份 `cloudfunctions/` 原始碼，配一個放在**專案目錄外**的 JSON 資料庫。切換：`node local-server/set-backend.js local ｜ cloud`，或設定頁的「數據後端」開關。
- ❌ **小程序內的假資料兜底（待刪）**：`repositories/*.js` 裡由 `config.allowSeedDataFallback` 控制的分支，不經過任何後端。`config.js` 從未定義那個開關 → 100% 不可達。

**刪第二個不影響第一個。**

### 2.2 開發環境的判斷不能只看 `appEnv`

`APP_ENV` 讀 `process.env`，而**小程序 runtime 沒有 `process`**（實測），所以它恆為 `'DEV'`，設成 PROD 關不掉任何開發工具。真正可靠的是 `wx.getAccountInfoSync().miniProgram.envVersion`。

- `config.isDev` = 開發者工具 + 體驗版
- `config.isDevTools` = **只有**開發者工具。會連 `localhost` 或換掉登入身份的東西一律用這個

### 2.3 測試「跑得過」不等於「驗到了」

- 導頁與讀資料是兩次獨立呼叫，用不同通道問「現在在哪一頁」會讀到別頁的資料。已修（讀狀態時一併回傳路由並核對），改測試時別重蹈。
- 布林權限欄位（`canSave`／`canEdit`／`isLoggedIn`）初始值就是 `false`，等就緒要傳 `v => v === true`。
- 冒煙 25 頁 PASS 25，但其中 8 頁只做到「有渲染出內容」的底線驗證。
